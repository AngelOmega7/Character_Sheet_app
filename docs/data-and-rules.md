# Reference data and stat calculations

## Delivered

- `tools/convert_reference_data.py` builds nine local JSON catalogs and a manifest from the local inventory. It never accesses Google Sheets.
- `zoids_app/catalog.py` loads local reference records by stable ID or trimmed display name.
- `zoids_app/stats.py` implements a deterministic calculation path for base, pilot-adjusted, and equipment-adjusted stats, carry penalties, fixed/removable weapon displays, selected abilities, frame/weapon upgrades, and Organoid bonuses.
- `zoids_app/preview.py` provides a runnable command-line preview before the Flet screens exist.
- `tests/fixtures/saberlion_snapshot.json` contains independently extracted cached spreadsheet expectations, not expectations generated by the new calculator.

All runtime modules use Python's standard library. Pandas/openpyxl are not required for this conversion: the earlier inventory already contains the XML cell/table data needed. They can be added to development tooling later if needed.

| TANK, FIGHTER, SCOUT, ALMIGHTY progression | 100 levels each |

The JSON also retains placeholders, two armament section headings, and four character-dependent equipment templates as explicitly tagged records. Blank table rows are listed as exclusions. Original sheet/row provenance, source headers, and original field values are retained. Text names are trimmed for display and ID generation; original names remain in the fields. Duplicate normalized IDs abort conversion.

Constant percentage formulas are converted to numeric fractions. Shared percentage formulas in Stats are resolved from their shared master. Character-dependent fields are marked with their formula and have **no cached value** in runtime data; they resolve against the selected character. In particular, Liger Zero's booster uses that character's computed speed, and the four armament templates look up that character's Zoid.

Per owner correction, legacy `NdM` weapon damage becomes the flat value **N × M**. Case and surrounding spaces are accepted: `18D10 explosive` becomes numeric damage 180, and `30d10 piercing` becomes 300. Weapon descriptions are converted inline too. Multi-shot wording is retained: “three bursts of 3D10” becomes “three bursts of 30,” with numeric damage 30 per burst, not 90. Supplemental wording from damage fields is retained in `damage_notes` and exposed as each calculated weapon's `damage_note`. Dynamic removable equipment inherits the converted value from its selected Zoid. Flat numeric values are unchanged; multiple dice terms in a single numeric damage field fail conversion for review rather than being guessed. Original values and source cells are preserved in `docs/generated/damage-conversions.json` and the untouched source inventory.

Description formulas are preserved for provenance; their cached text is used as reference prose. Feats remain descriptions, not automatically enforced turn/combat logic in this stat-calculation milestone.

## Model and API

```python
from zoids_app.stats import CharacterBuild, Upgrades, calculate_stats

build = CharacterBuild(
    zoid="zoids:saberlion",
    pilot_style="FIGHTER",
    pilot_level=1,
    mental=3,
    abilities=("abilities:lion_type_1",),
    upgrades=Upgrades(damage=(1, 0, 0, 0)),
)
stats = calculate_stats(build)
assert stats["pilot"]["health"] == 144
```

Upgrade inputs are **points**, each 0–5. Frame multipliers are speed 30, reaction 1, defense 5, capacity 10. Fixed weapon damage is 20/point and to-hit is 1/point. Only fixed slots 1–4 accept either weapon upgrade. Per owner clarification, to-hit upgrades also add a flat +1/point to the final attack bonus after pilot/modifier rounding; pilot percentages and overload penalties do not scale this added bonus. Slots 5–8 receive no weapon upgrades. The workbook's saved E12 value of 20 is imported as one damage point, not 20 points. Purchasing upgrades, restricting upgrades to eligible weapons, and sharing ownership across CAS forms belong to the later character-management layer; the calculator applies a supplied build.

Equipment and fixed activation flags are independent of attacks, heat, and broken status. A combat controller will reconcile these when the UI is built. Calculations never modify current health, shield damage, gold, heat, or weapon condition. Numeric arithmetic uses Decimal and explicit spreadsheet half-away-from-zero / away-from-zero rounding. UI serialization can convert final numeric results as needed.

## Ability ownership and size bonuses

`zoids_app/abilities.py` manages an `AbilityLoadout` with active and inactive lists. `CharacterBuild.abilities` contains up to six active slots; `inactive_abilities` stores owned abilities that contribute no bonuses.

- At most **one size bonus ability** can be active, even if a second ability targets a different size. Multiple size families may be owned inactive.
- Numbered names are ranks of one ability family; an unnumbered name is rank 1. Family matching ignores capitalization and handles the source typo `BLOXType 1` as the BLOX Type family.
- `learn_ability()` places a new family in inactive storage. A higher rank replaces the owned lower rank in its existing active slot or inactive position. The lower rank is removed, not moved to inactive storage. Downgrades are rejected.
- `activate_ability()` moves an owned inactive ability into a chosen slot, storing the displaced ability inactive. It rejects a second active size ability in another slot. `deactivate_ability()` moves the selected ability inactive.
- Calculation validates both lists so duplicate ranks/families cannot sneak into a build. No rank history is persisted yet; future save/UI code must use these transitions rather than replacing ownership lists arbitrarily.
- Size matching uses exact, case-insensitive categories. `Large` does not match `Extra Large` or `Large Large`. Comma-separated categories such as `Medium, Small` explicitly support both sizes.
- The matching size percentage contributes to health, armor, reaction, range, and now **all eight weapon to-hit modifiers**. It adds to the pilot percentage before multiplication/rounding. Fixed-weapon flat to-hit upgrades are added afterward.
- Medium Under Expert 4 is corrected to **0.25 (25%)**. The original value 25 and reason are retained in the record's correction metadata.

Example: base to-hit 17, pilot bonus 25%, size bonus 10%, and two fixed upgrade points give `ROUND(17 × 1.35) + 2 = 25`.

## Organoid activation

All Organoid contributions are gated by `CharacterBuild.organoid_enabled`. Selecting a color and level alone grants no bonuses. When activated, the Organoid's to-hit percentage now contributes to all eight weapon slots, alongside the pilot and matching size percentages, before rounding. Flat fixed-weapon upgrades are added afterward.

Example: base to-hit 17, pilot bonus 25%, size bonus 10%, Black level 5 Organoid bonus 25%, and two fixed upgrade points give `ROUND(17 × 1.60) + 2 = 29`.

Deactivation removes the Organoid contributions to maximum health, armor, speed, range, shields, weapon damage, and weapon to-hit. It does not alter saved current health, shield damage, heat, gold, or weapon condition. Tests cover activation/deactivation for all four colors and confirm the complete calculated result returns to its non-Organoid baseline. Source shield lookup/mapping and damage-column discrepancies listed below remain separate issues.

## Active speed and contextual attack abilities

Fleet Footed ranks add their existing +50/+100/+150/+200 speed values whenever active. These are flat additions to current speed after base/pilot/Organoid calculations, alongside equipment bonuses. Inactive owned skills contribute nothing. Slowpoke and the other retired drawback families are removed.

`zoids_app.attacks.calculate_attack()` previews a selected weapon's attack modifier and flat damage using current health and a per-attack range selection. It is separate from `calculate_stats()` because range and current health are attack context, not reference data. It does not roll, fire, change heat, check broken state, or spend resources; the future combat controller must use it with the existing weapon-use rules.

- **Sniper 1–4:** +1/+2/+3/+4 to-hit, only when active and the selected ranged attack is Long Range. This is not a maximum-range bonus. Both fixed and removable ranged weapons are eligible.
- **Comeback 1–4:** +20%/+30%/+40%/+50% damage, only when active and current health is **at or below 20%** of the latest calculated maximum health. This applies to melee and ranged attacks. Percentages add to Organoid damage percentage on the base damage plus fixed damage upgrades, with one final spreadsheet-style rounding; they do not multiply one another. Original descriptions/values are retained in correction metadata.
- **Future range controls:** Long Range (>half current maximum range), Close Range (within 60m), Normal Range (>60m and <=half maximum range). Store one mutually exclusive selection per ranged attack; hide/ignore it for melee. Code accepts a band or optional distance; the UI is pending.
- **Boundary:** exactly half maximum range is always Normal, per owner. Other Close/Long overlap for short maximum ranges raises a clarification error in distance classification; explicit selection is still available.
- Ranged classification currently uses the `Ranged` damage-type tag, excluding `Melee`. Some older Zoid-specific equipment has only `Energy`/`Piercing` tags despite ranged descriptions; these need explicit tag cleanup before their range-dependent effects can be automated reliably.

See [Ability review](ability-review.md) for the remaining ability discrepancies and descriptive effects awaiting implementation.

## Source issues requiring owner decisions

### Equipment activation correction

Each removable equipment slot contributes its own armor, defense, reaction, speed, range, to-hit, and shield bonuses only when that item is passive or its activation flag is on. A passive item contributes automatically while equipped, including in the chest slot. Empty slots contribute nothing. Activation never enables bonuses from another inactive item. Equipped weight still counts whether an item is activated or not.

The fixed slot 2/3 speed, range, to-hit, and reaction modifier fields also use their own activation/passive state. Ability reaction bonuses remain additive. True Tank applies per enabled defensive item; Evasion Master adds Armor per enabled reaction-boosting item. Shield Master adds to the combined positive Shield HP pool independent of source. See `ability-review.md` for the confirmed rules.

### Dashboard review deferred

Owner decision: the Dashboard is an intermediate spreadsheet calculation layer, not an app feature. Keep it as migration reference and defer its remaining discrepancies until a gameplay requirement makes them relevant. Python handles runtime calculations directly; no Dashboard screen or runtime worksheet is needed.

Findings below marked **Deferred (Dashboard)** are retained for future reference, not queued for immediate correction. Deferral does not resolve those findings or alter the existing Python behavior and owner-confirmed corrections.

## Verification and limits

The saved example matches base/pilot/current stat groups, carry values, bonus levels, shields, standard weapon range, and all eight to-hit displays. It has health 144, armor 21, defense 8, speed 255, reaction 24, range 625, and carry capacity 20.

Additional tests exercise all 157 Zoids across four pilot styles at level 100; exact-capacity/overload transitions; underlevel penalties; ability ownership/rank replacement and active/inactive switching; exact size matching and attack percentages; passive/active equipment; dynamic equipment and boosters; all Organoid colors at levels 0 and 40; rounding; and invalid levels/upgrade points. These are formula-based and invariant checks, **not independently recalculated Google Sheets snapshots for every build**.

Levels outside reference tables fail explicitly rather than being silently clamped. Further reference configurations and owner decisions on the findings above are needed before claiming complete spreadsheet parity. Turn durations, inventory/currency UI, purchase eligibility, CAS sharing, feats, transport modules, and combat orchestration are later features, not completed by this calculation module.
